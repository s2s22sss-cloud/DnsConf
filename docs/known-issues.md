# Известные проблемы

Ошибки и ограничения текущей версии. Пункты, отмеченные «возможно», следуют
из чтения кода, но не проверены на живом API.

Когда проблема исправлена, удалите её отсюда (см. [Ведение документации](dev/docs-guide.md)).

## Cloudflare

### Обновление не атомарно

Старые правила и списки удаляются до создания новых. При сбое посреди запуска
часть блокировок и перенаправлений будет отсутствовать до следующего успешного
запуска. Порядок сохранён сознательно: если сначала создавать новые объекты,
на время запуска количество списков удваивается, и с большими hosts-файлами
можно упереться в лимит бесплатного тарифа.

### Домен одновременно в `BLOCK` и `REDIRECT`

**Возможно.** Если домен есть и в источниках блокировок, и в источниках
перенаправлений, в Cloudflare будут созданы оба правила. Какое сработает,
решает precedence: у правила блокировки он `0`, у перенаправлений — от `1`,
поэтому, скорее всего, домен будет заблокирован.

## NextDNS

### Удалённые из источника записи остаются

Это особенность стратегии, а не сбой: домены, пропавшие из источников, не
удаляются ни из denylist, ни из rewrites. Записи скрипта ничем не помечены,
поэтому отличить их от ручных нельзя. Полная пересинхронизация — разовый запуск
с `NEXTDNS_CLEAR_ALL=true` (удалит и ручные записи), см.
[NextDNS](user/nextdns.md#полная-очистка-nextdns_clear_all).

## Исправлено

Для истории — проблемы, исправленные после появления документации:

- Cloudflare терял последнюю тысячу доменов, если их число было кратно 1000.
- Строки hosts с табуляцией роняли скрипт.
- Пробелы после запятых в `BLOCK` / `REDIRECT` роняли скрипт.
- Комментарии в строке, несколько доменов в строке и служебные записи
  (`broadcasthost`, `ff02::1`, …) разбирались неверно.
- Код ответа источника не проверялся, редиректы не выполнялись.
- Дубликаты после удаления `www.` попадали в списки.
- NextDNS: при пустых `BLOCK` и `REDIRECT` удалялись все записи профиля,
  включая ручные. Теперь — только по флагу `NEXTDNS_CLEAR_ALL=true`.
- NextDNS: для выключенных записей denylist отправлялся повторный `POST`.
- NextDNS: в логе выводилось неверное число источников rewrites.
- Cloudflare: `result: null` в ответе `GET /rules` мог привести к `NullPointerException`.
- Утечка разрешений семафора в `HttpRequestSender` при сетевой ошибке.
