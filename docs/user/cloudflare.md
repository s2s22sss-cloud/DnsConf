# Cloudflare Zero Trust

## Получение учётных данных

1. Зарегистрируйтесь в Cloudflare, откройте вкладку **Zero Trust** и создайте
   организацию.
   - Выберите бесплатный тариф (Free).
   - На шаге ввода платёжных данных нажмите *Cancel and exit* (правый верхний угол)
     и вернитесь во вкладку *Zero Trust*.
2. Создайте API-токен на https://dash.cloudflare.com/profile/api-tokens
   с двумя разрешениями:
   - `Account` → `Zero Trust` → `Edit`
   - `Account` → `Account Firewall Access Rules` → `Edit`

   Токен — это `AUTH_SECRET`.
3. Скопируйте Account ID: https://dash.cloudflare.com/?to=/:account/workers.
   Это `CLIENT_ID`.

## Поведение скрипта

На каждом запуске скрипт **полностью пересоздаёт** свои объекты в
*Zero Trust → Gateway*. Чужие объекты (созданные вручную или другими
инструментами) он не трогает.

### Как скрипт узнаёт свои объекты

| Объект | Признак |
|---|---|
| Список блокировок | Имя начинается с `Blocked websites by script` |
| Список перенаправлений | Имя начинается с `Override websites by script` |
| Правило | Имя начинается с `Rules set by script` |

В поле *Description* каждого объекта записывается идентификатор сессии (UUID),
новый на каждый запуск. Удаляются объекты с «своим» именем и **другим**
идентификатором сессии, то есть всё, что создали прошлые запуски.

> Не называйте собственные списки и правила с этих префиксов — скрипт их удалит.

### Порядок действий

1. Скачать и разобрать источники `BLOCK` и `REDIRECT`.
2. Удалить старые правила (`Rules set by script…`).
3. Удалить старые списки.
4. Если есть домены для блокировки:
   - создать списки `Blocked websites by script 1`, `… 2`, … по 1000 доменов;
   - создать одно правило `Rules set by script` с действием **block**,
     которое срабатывает, если домен есть в любом из этих списков.
5. Если есть перенаправления:
   - сгруппировать домены по целевому IP;
   - для каждого IP создать списки `Override websites by script to IP <ip> N`
     по 1000 доменов;
   - для каждого IP создать правило `Rules set by script override to IP -> <ip>`
     с действием **override** на этот IP.

Если `BLOCK` или `REDIRECT` пуст, соответствующие объекты будут удалены (шаги 2–3)
и не созданы заново. Так можно очистить настройки: запустите скрипт без источников.

### Приоритет правил (precedence)

Правилам перенаправления назначаются свободные значения precedence начиная с 1,
пропуская значения, уже занятые оставшимися в аккаунте правилами. Это
исключает конфликт номеров. Правило блокировки отправляется с precedence `0`.

### Что важно знать

- **Операция не атомарна** (см. [Известные проблемы](../known-issues.md#обновление-не-атомарно)). Старые правила удаляются до создания новых. Если
  запуск упадёт посередине, в аккаунте какое-то время не будет части правил;
  следующий успешный запуск всё восстановит.
- Размер списков ограничен 1000 доменами, поэтому большие источники
  превращаются в множество списков. У бесплатного тарифа есть лимит на
  количество списков: с очень большими hosts-файлами можно в него упереться.
- Если хотя бы один источник недоступен или отвечает ошибкой, скрипт
  останавливается **до** удаления старых объектов — текущие правила остаются.

## Ошибки авторизации

| Код | Сообщение в логе | Что проверить |
|---|---|---|
| 401 | `Invalid API Token!` | Токен скопирован целиком, не отозван |
| 403 | `Token doesn't have necessary permissions!` | Оба разрешения из шага 2; `CLIENT_ID` — ID того же аккаунта |

Скрипт при этом сразу завершается с кодом 1.
