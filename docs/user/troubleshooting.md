# Диагностика

## Как читать лог

| Префикс | Значение |
|---|---|
| `#==#==# … #==#==#` | Начало и конец работы (`CLOUDFLARE` / `NextDNS`, `FINISHED`) |
| `--- …` | Этап работы |
| `>>> …` | Сетевая операция: загрузка источника, запрос к API |
| `!!! …` | Ошибка или предупреждение |
| `N/M` | Прогресс (в GitHub Actions строки прогресса могут склеиваться) |

`!!! Websites to block were not provided` или `!!! No block sources provided` —
не ошибка, а сообщение о том, что соответствующая переменная пуста.

При ошибке HTTP в лог пишется полный запрос:

```
!!! Failed request on POST https://api.../lists with payload:
{...}
Code: 400, reason:
{...ответ API...}
```

Причину обычно видно в `reason`.

## Частые проблемы

### `Не обнаружена обязательная переменная среды: CLIENT_ID`

Секрет не передан в job. Проверьте:
- окружение называется ровно `DNS`;
- `CLIENT_ID` и `AUTH_SECRET` лежат в **Environment secrets** именно этого
  окружения, а не в *Repository secrets* другого окружения;
- имена переменных без опечаток и пробелов.

### `Unsupported DNS provider! Must be CLOUDFLARE or NEXTDNS`

Значение `DNS` должно быть `Cloudflare` или `NextDNS` (регистр не важен),
без пробелов и кавычек.

### `IllegalArgumentException: Illegal character in scheme name at index 0`

В `REDIRECT` или `BLOCK` есть пробел — чаще всего после запятой.
Уберите пробелы: `https://a/hosts,https://b/hosts`.

### `StringIndexOutOfBoundsException: Range [0, -1)`

В одном из hosts-файлов IP и домен разделены табуляцией. См.
[Источники данных](data-sources.md#требования-к-содержимому).

### Ошибка API с IP вроде `404:` или `<html>`

Ссылка-источник вернула не hosts-файл: страницу ошибки или HTML. Откройте
ссылку в браузере; используйте `raw.githubusercontent.com`.

### Ничего не применилось, ошибок нет

- Источник пуст или содержит строки только другого типа (например, в `BLOCK`
  указан файл без строк `0.0.0.0 …`).
- Ссылка ведёт на редирект (короткая ссылка, `github.com/.../blob/...`):
  редиректы не выполняются, тело ответа пустое.

### 401 / 403

Неверный ключ или недостаточно прав. Cloudflare — см.
[права токена](cloudflare.md#ошибки-авторизации); NextDNS — проверьте ключ и
ID профиля.

### NextDNS: запуск идёт часами

Ожидаемо для больших списков: ~60 запросов в минуту. См.
[рекомендации](nextdns.md#рекомендуемая-настройка).

### Cloudflare: ошибка при создании списка или превышение лимита

Проверьте `reason` в логе. Частые причины — пустой список (см.
[Известные проблемы](../known-issues.md#cloudflare-теряется-последняя-тысяча-доменов))
и лимит количества списков бесплатного тарифа.

## Не нашли ответ

Посмотрите [Известные проблемы](../known-issues.md). Если проблемы там нет,
создайте issue с логом шага *Run application* — **удалив из него** ключи и ID.
