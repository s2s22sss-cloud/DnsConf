# NextDNS

## Получение учётных данных

1. Создайте API-ключ на https://my.nextdns.io/account — это `AUTH_SECRET`.
2. Нажмите на логотип NextDNS, на открывшейся странице скопируйте ID из блока
   *Endpoints* — это `CLIENT_ID` (ID профиля).

## Рекомендуемая настройка

Задайте только `REDIRECT`, а блокировки включите встроенными списками на
вкладке *Privacy*. API NextDNS принимает около 60 запросов в минуту, и каждый
домен — отдельный запрос, поэтому загрузка большого блок-листа через скрипт
занимает часы.

## Поведение скрипта

В отличие от Cloudflare, скрипт **не помечает** свои записи: он работает со всем
denylist и всеми rewrites профиля.

### `BLOCK` → Denylist

1. Скачать и разобрать источники.
2. Получить текущий denylist профиля.
3. Убрать из нового списка домены, уже присутствующие в denylist как активные.
4. Добавить оставшиеся домены.

Ничего не удаляется: домен, исчезнувший из источника, останется в denylist.

### `REDIRECT` → Rewrites

1. Скачать и разобрать источники; для повторяющихся доменов взять первый IP.
2. Получить текущие rewrites профиля.
3. Для каждого существующего rewrite:
   - домен есть в источниках с **другим** IP → старая запись удаляется,
     новая будет создана;
   - иначе запись остаётся как есть.
4. Создать rewrites для новых и изменившихся доменов.

Rewrites, которых больше нет в источниках, не удаляются.

### Пустые `BLOCK` и `REDIRECT` одновременно

Скрипт **удаляет весь denylist и все rewrites профиля** — в том числе записи,
добавленные вручную. Если у вас есть ручные записи, не запускайте скрипт без
источников. См. [Известные проблемы](../known-issues.md#nextdns-очистка-удаляет-ручные-записи).

## Ограничение скорости API

Запросы отправляются по одному. Когда NextDNS отвечает `429` (rate limit)
или `524` (timeout), скрипт:

1. возвращает запрос в конец очереди;
2. выводит фактическую скорость отправки;
3. ждёт 60 секунд с обратным отсчётом (`Waiting for reset: N seconds`);
4. продолжает.

Любой другой HTTP-код ошибки останавливает скрипт (код выхода 1). Ошибки,
пришедшие в теле успешного ответа (`errors`), записываются в лог как
`Failed request: …`, и запрос не повторяется.

Время работы в GitHub Actions ограничено 6 часами на job. Если
синхронизация не успевает, уменьшите объём источников или разнесите их по
нескольким запускам.

## Ошибки авторизации

Коды 401 и 403 выводятся как `Invalid api key!`, и скрипт завершается.
Проверьте и `AUTH_SECRET`, и `CLIENT_ID`: неверный ID профиля тоже даёт отказ
в доступе.
