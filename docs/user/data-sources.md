# Источники данных

Источник — это ссылка на файл в формате hosts:

```
# комментарий
0.0.0.0     ads.example.com
127.0.0.1   tracker.example.com
1.2.3.4     www.blocked-in-region.example  cdn.blocked-in-region.example
```

Один и тот же файл можно указать и в `BLOCK`, и в `REDIRECT`: каждый режим
возьмёт из него только свои строки.

## Как разбирается файл

Код: `com.novibe.common.data_sources` (`HostsLine`, `ListLoader`,
`HostsBlockListsLoader`, `HostsOverrideListsLoader`).

1. Все источники скачиваются параллельно, затем склеиваются **в порядке,
   указанном в переменной**.
2. Файл режется на строки (`\n` или `\r\n`).
3. Всё после `#` отбрасывается (комментарии целиком и в конце строки),
   пробелы по краям убираются, пустые строки пропускаются.
4. Строка переводится в нижний регистр и делится по любым пробельным символам
   (пробелы, табуляция) на `IP` и один или несколько доменов.
5. Строка, где первое слово не IP-адрес, пропускается. Количество таких строк
   выводится в лог: `skipped N lines not in "<ip> <domain>" format`.
6. У доменов убирается префикс `www.`. Отбрасываются имена без точки
   (`localhost`, `broadcasthost`, `ip6-allnodes`), `localhost.localdomain`,
   `*.localhost`, `*.local` и имена с недопустимыми символами (например, `*`).
7. Строка относится к блокировкам, к перенаправлениям или ни к чему (см. ниже).
8. Повторяющиеся результаты удаляются; остаётся первое вхождение.

### Блокировки (`BLOCK`)

Строки, где IP — `0.0.0.0`, `127.0.0.1`, `::1` или `::`. Результат — список доменов.

```
0.0.0.0 domain.to.block              → domain.to.block
127.0.0.1	www.another.block          → another.block
0.0.0.0 a.block b.block              → a.block, b.block
1.2.3.4 domain.to.redirect           → (пропущено)
127.0.0.1 localhost                  → (пропущено)
```

### Перенаправления (`REDIRECT`)

Строки, где IP — обычный адрес, на который можно перенаправить: не адрес
блокировки и не служебный. Служебные адреса, которые пропускаются:
`0.x.x.x`, `127.x.x.x`, `169.254.x.x`, `224.0.0.0` и выше (мультикаст,
широковещательный `255.255.255.255`), IPv6 `ff…` (мультикаст), `fe80:…`
(link-local) и адреса с зоной (`%lo0`).

```
1.2.3.4 domain.to.redirect           → domain.to.redirect → 1.2.3.4
1.2.3.4	www.site.example # comment   → site.example → 1.2.3.4
5.6.7.8 a.example b.example          → a.example → 5.6.7.8, b.example → 5.6.7.8
2001:db8::1 v6.example               → v6.example → 2001:db8::1
255.255.255.255 broadcasthost        → (пропущено)
0.0.0.0 domain.to.block              → (пропущено)
```

Если домен встречается несколько раз, применяется IP из первого вхождения
(с учётом порядка источников).

## Требования к ссылкам

- Ссылка должна вести на сам файл. HTTP-редиректы выполняются, поэтому
  короткие ссылки работают, но ссылка вида `github.com/<user>/<repo>/blob/...`
  вернёт HTML-страницу, а не файл. Используйте `raw.githubusercontent.com/...`.
- Если источник отвечает кодом, отличным от 2xx (например, 404), или не
  открывается, скрипт **останавливается до изменения настроек** провайдера
  с сообщением `Failed to load … list from url`. Это защищает от ситуации,
  когда из-за недоступного источника были бы удалены все правила.
- Ссылки перечисляются через запятую; пробелы и переводы строк вокруг
  запятых допустимы.
