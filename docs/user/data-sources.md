# Источники данных

Источник — это ссылка на файл в формате hosts:

```
# комментарий
0.0.0.0     ads.example.com
127.0.0.1   tracker.example.com
1.2.3.4     www.blocked-in-region.example
```

Один и тот же файл можно указать и в `BLOCK`, и в `REDIRECT`: каждый режим
возьмёт из него только свои строки.

## Как разбирается файл

Код: `com.novibe.common.data_sources` (`ListLoader`, `HostsBlockListsLoader`,
`HostsOverrideListsLoader`).

1. Все источники скачиваются параллельно, затем склеиваются **в порядке,
   указанном в переменной**.
2. Файл режется на строки (`\n` или `\r\n`).
3. Отбрасываются пустые строки и строки, начинающиеся с `#`.
4. Строка переводится в нижний регистр.
5. Строка относится к блокировкам или к перенаправлениям (см. ниже).
6. Полностью одинаковые строки удаляются.
7. Из домена убирается префикс `www.`.

### Блокировки (`BLOCK`)

Берутся строки, начинающиеся с `0.0.0.0 `, `127.0.0.1 ` или `::1 ` (с пробелом
после адреса). Исключаются строки, оканчивающиеся на `localhost` или
`ip6-localhost`. Результат — список доменов.

```
0.0.0.0 domain.to.block        → domain.to.block
127.0.0.1 www.another.block    → another.block
1.2.3.4 domain.to.redirect     → (пропущено)
127.0.0.1 localhost            → (пропущено)
```

### Перенаправления (`REDIRECT`)

Берутся **все остальные** строки, то есть всё, что не попало под правило
блокировки. Всё до первого пробела считается IP, остаток (без пробелов по
краям) — доменом.

```
1.2.3.4 domain.to.redirect     → domain.to.redirect → 1.2.3.4
1.2.3.4     www.site.example   → site.example → 1.2.3.4
0.0.0.0 domain.to.block        → (пропущено)
```

Если домен встречается несколько раз, применяется IP из первого вхождения
(с учётом порядка источников).

## Требования к ссылкам

- **Прямая ссылка на файл.** Редиректы HTTP не выполняются, поэтому ссылка вида
  `github.com/<user>/<repo>/blob/...` вернёт не файл. Используйте
  `raw.githubusercontent.com/...`.
- **Код ответа не проверяется.** Если по ссылке страница 404 или HTML,
  скрипт попробует разобрать её как hosts-файл. Обычно это заканчивается
  ошибкой API провайдера с бессмысленным «IP» вроде `404:`.
- **Без пробелов** вокруг запятых в переменной.

## Требования к содержимому

Строки, которые сейчас разбираются некорректно (подробнее —
[Известные проблемы](../known-issues.md)):

| Строка | Что произойдёт |
|---|---|
| `1.2.3.4<TAB>site.example` (табуляция вместо пробела) | Падение скрипта с `StringIndexOutOfBoundsException` |
| `0.0.0.0<TAB>site.example` | То же: строка не распознаётся как блокировка и уходит в разбор перенаправлений |
| `1.2.3.4 a.example b.example` (несколько доменов) | Доменом станет `a.example b.example` целиком |
| `1.2.3.4 site.example # комментарий` | Комментарий попадёт в имя домена |
| `255.255.255.255 broadcasthost`, `ff02::1 ip6-allnodes` | Будут восприняты как перенаправления |

Если используете собственный файл, придерживайтесь формата
«один IP, один пробел или несколько, один домен, без комментариев в строке».
